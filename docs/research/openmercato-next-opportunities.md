# Open Mercato: next developer/product opportunities

Checked 2026-09-16 against official source and documentation. These are recommendations for Trykatch, not implementation instructions. “Implemented” below means present in upstream source, not proof the same feature exists in Trykatch or every published package.

1. **Durable operations with one progress contract.** Implemented: local/BullMQ queue strategies, worker concurrency and retries; server-persisted `ProgressJob`, cancellation checks, heartbeats, tenant/organization scope, and a shared progress surface. The catalog bulk-delete worker demonstrates typed payloads and failure propagation. Opportunity: an opinionated start-operation API returning a job ID, reusable worker wrapper, retry/cancel UX, and navigation-safe progress for imports, exports and bulk actions. This prevents each feature inventing its own background-work lifecycle. [Queue package](https://github.com/open-mercato/open-mercato/blob/main/packages/queue/README.md), [progress contract](https://github.com/open-mercato/open-mercato/blob/main/packages/core/src/modules/progress/AGENTS.md), [implemented worker](https://github.com/open-mercato/open-mercato/blob/main/packages/core/src/modules/catalog/workers/catalog-product-bulk-delete.ts).

2. **Module-declared notifications and reactive effects.** Implemented: notification type declarations, custom client renderers and idempotent notification handlers. SSE delivers scoped notifications and fan-out updates; polling remains fallback. Opportunity: a typed notification registry plus shared inbox/preferences/actions and a notification-effect hook, so completion/failure events can update pages without feature-local polling. [Module contracts](https://github.com/open-mercato/open-mercato/blob/main/packages/core/AGENTS.md), [notification delivery](https://github.com/open-mercato/open-mercato/blob/main/packages/core/src/modules/notifications/README.md).

3. **Typed form/filter extension contracts, with deliberate custom-field round trips.** Implemented: injected field types include async option loaders, cache TTL, placement, visibility rules and custom renderers; injected filters explicitly choose server or client strategy. Custom fields have declaration helpers, response normalization and undo snapshot/reset conventions. Opportunity: complement existing table-column/action seams with stable form/group IDs, typed field/filter declarations, and shared custom-field serialize/restore helpers. Avoid promising fully inferred domain types: several upstream callback/value surfaces still use `unknown`. [Public extension types](https://github.com/open-mercato/open-mercato/blob/main/packages/shared/src/modules/widgets/injection.ts), [custom-field conventions](https://github.com/open-mercato/open-mercato/blob/main/packages/core/AGENTS.md).

4. **Auditable, optionally undoable commands.** Implemented: `CommandBus` captures before/after snapshots, persists action logs, invokes interceptors and invalidates caches. Undo requires a handler, atomically claims the action-log row, and releases its claim on failure. Opportunity: an opt-in command contract and common last-operation/undo UX for recoverable mutations—not a promise every deletion or external side effect can be reversed. [Command implementation](https://github.com/open-mercato/open-mercato/blob/main/packages/shared/src/lib/commands/command-bus.ts).

5. **An integration developer kit with operational visibility.** Implemented: streaming import/export adapters, cursor persistence, item-level errors, overlap protection, retry/resume and cancellation; webhook test-send, delivery logs/manual retry, signed delivery, rotation and inbound adapters. Opportunity: shared adapter contracts, scoped credentials, connection validation and a run/delivery inspector. Important boundary: HTTP webhook delivery is documented as available; SQS/SNS are explicitly planned. [Data-sync contracts](https://github.com/open-mercato/open-mercato/blob/main/packages/core/src/modules/data_sync/AGENTS.md), [webhook guide](https://github.com/open-mercato/open-mercato/blob/main/apps/docs/docs/framework/webhooks/overview.mdx).

6. **Version-correct AI developer context with executable evaluation.** Implemented documentation describes generated module facts, exact-installed-source resolution, bounded context, disposable writable cases, trusted behavior/AST oracles and isolated review. Opportunity: machine-readable extension facts plus a small evaluation catalog proving agents choose supported seams and generate valid code, rather than expanding root instructions indefinitely. [Harness architecture](https://github.com/open-mercato/open-mercato/blob/main/apps/docs/docs/architecture/standalone-ai-development-harness.mdx).
