# AI delivery goal: requirements and evidence

Goal: finish the requested Open Mercato-inspired AI developer/product plan with enterprise-oriented architecture and Microsoft's provider-neutral .NET abstractions. This audit preserves the whole requested AI scope; it does not treat the earlier read-only runtime or chat milestone alone as completion. Open Mercato's separate durable operations, notifications, integrations and undo recommendations are not silently folded into AI work.

## Requirements recovered from the conversation and existing artifacts

1. Developer experience: project-local task instructions/skills, installed-version module discovery, supported generator/extension seams and falsifiable verification guidance. Evidence: shipped `.agents/skills`, `AGENTS.md`, read-only `module facts`, module doctor/facts tests and renamed packed-template checks. Skills do not execute inside the product chat.
2. Explicit assistant contract: build-time OpenAPI/TanStack client and a deny-by-default assistant-tool catalog. Evidence: stable operation IDs, module descriptors, generated `docs/generated/assistant-contract.json`, drift checks, module composition/architecture tests. A descriptor alone never activates execution or confirmation.
3. Provider-independent runtime: `Microsoft.Extensions.AI.IChatClient`, explicit provider/model/configuration, OpenAI Responses, native Ollama and configurable Chat Completions including DeepSeek UAT. Evidence: the same runtime/adapters' deterministic conformance tests. No vendor-shaped module interface, implicit provider, automatic fallback, arbitrary endpoint selection or automatic paid retries. Native adapters for every vendor are not promised.
4. Secured workspace integration: authenticated active membership, actor/organization derived from request context, cookie antiforgery, per-actor/global limits, module permission rechecks, organization transactions, EF ownership and forced PostgreSQL RLS. Evidence: production HTTP tests against real PostgreSQL under separated runtime roles, foreign/missing scope and forbidden read/write tests. File content/object keys and elevated principals never reach the model.
5. Product help UX: floating/account-menu AI Help chat, clean transcript, send-and-clear, Enter/Shift+Enter, loading/cancel/error recovery, responsive/dark-mode/French affordances, reset and follow-up context. Evidence: React tests and real-browser flows, including expired/access-changed continuation and late-response cleanup. Scope-bound encrypted continuation remains bounded and nonpersistent.
6. Architecture/module learning: deployment-safe approved guides, deterministic bounded retrieval, actual enabled module declarations, follow-ups and inspectable server-issued guide sources. Evidence: `assistant-guidance.md`, embedded corpus, retrieval evaluation cases, all-provider knowledge-only conformance, no-record-permission HTTP scenario and guide-page/browser tests. This is not arbitrary repository/code/shell access.
7. Operator setup and honest readiness: server-only secrets, local Development/UAT instructions, production key-ring/configuration boundaries, generated full-stack/backend-only compatibility, broad applicable gates and a bounded real DeepSeek UAT evaluation with operator approval. Fake providers/browser mocks cannot prove live answer quality. Local tests do not certify all enterprise deployment/recovery/replica conditions or publish a release.

## Boundaries not to misrepresent

Writes/approval execution, autonomous agents, MCP hosting, persistent saved chats, streaming, cross-replica quota storage, a generative coding-agent judge and ready-made native adapters for all vendors were not delivered by the original read-only AI plan. Enabling them requires their own reviewed security/product contracts; the presence of an upstream Open Mercato feature or proposed opportunity does not authorize activation here. Multi-replica deployments must share the configured Data Protection application/key ring, and in-process rate limits are per replica. Follow the separate production-readiness plan for release/operational certification.
