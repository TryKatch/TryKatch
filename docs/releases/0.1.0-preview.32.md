# Trykatch 0.1.0-preview.32

## English

Coordinated CLI/template preview candidate that keeps Trykatch marketing on the Trykatch website and removes it from newly generated React applications. Availability requires successful exact-main CI, sealed qualification of the release package pair and trusted publication; candidate metadata does not prove publication.

```bash
dotnet tool update --global Trykatch.Cli --version 0.1.0-preview.32
trykatch update --version 0.1.0-preview.32
# First installation: use dotnet tool install instead of update.
```

- Newly generated React applications open at their branded sign-in experience instead of shipping Trykatch's marketing homepage.
- Generated packages exclude the landing-page component, launch video, landing preferences, marketing Storybook story and landing-page browser test.
- The Trykatch source website keeps its existing public landing page, launch video, preferences and marketing tests.
- Shared routing keeps authentication, invitations, password recovery, organization selection and application routes consistent between the source website and generated applications.
- Packaging qualification verifies both sides of the boundary: generated output has no marketing route or assets, while source builds retain the Trykatch landing page.
- Display-name qualification now checks generated authentication and application surfaces and explicitly rejects a generated landing page.
- Organization AI settings, role selection, shared floating controls, Storybook coverage and security boundaries from preview.31 remain included.

The complete Storybook inventory, automatically generated CRUD/workflow stories, full application-wide responsive matrix, simultaneous authorization-revocation race proof and real production-provider UAT remain outside this candidate. This preview is not an enterprise certification. The release pipeline must separately qualify the exact packages before publication.

Updating the installed template does not rewrite existing generated applications. Newly generated React projects include this change; existing customized projects require a reviewed route and asset update.

## Français

Candidat de préversion coordonnée CLI/template qui conserve le marketing Trykatch sur le site Trykatch et le retire des nouvelles applications React générées. La disponibilité exige la CI du commit exact sur main, la qualification scellée des deux paquets et la publication de confiance.

```bash
dotnet tool update --global Trykatch.Cli --version 0.1.0-preview.32
trykatch update --version 0.1.0-preview.32
```

Pour une première installation, utiliser `dotnet tool install` au lieu de `update`.

- Les nouvelles applications React générées s'ouvrent sur leur écran de connexion personnalisé et n'embarquent plus la page marketing Trykatch.
- Le paquet généré exclut le composant de landing page, la vidéo de lancement, les préférences marketing, la story Storybook et le test navigateur de cette page.
- Le site source Trykatch conserve sa page publique, sa vidéo, ses préférences et ses tests marketing.
- Le routage partagé conserve l'authentification, les invitations, la récupération du mot de passe, la sélection d'organisation et les routes applicatives.
- La qualification vérifie les deux côtés de la séparation : aucune route ou ressource marketing dans le projet généré, et conservation de la landing page dans le site source.
- La qualification du nom d'affichage vérifie les écrans d'authentification et d'application générés et refuse explicitement une landing page générée.
- La configuration IA par organisation, l'attribution des rôles, les champs flottants partagés, Storybook et les limites de sécurité de preview.31 restent inclus.

La couverture Storybook exhaustive, les stories CRUD/workflow automatiques, la matrice responsive complète, la preuve d'une course de révocation simultanée et l'UAT avec un fournisseur réel restent hors de ce candidat. Ce n'est pas une certification entreprise.

La mise à jour du template ne réécrit pas les applications existantes. Les nouveaux projets React incluent ce changement ; les projets personnalisés existants nécessitent une mise à jour revue des routes et ressources.
