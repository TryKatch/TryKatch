# Trykatch 0.1.0-preview.31

## English

Coordinated CLI/template preview candidate for organization-owned AI subscription settings and consistent floating forms. Availability requires successful exact-main CI, sealed qualification of the release package pair and trusted publication; candidate metadata does not prove publication.

```bash
dotnet tool update --global Trykatch.Cli --version 0.1.0-preview.31
trykatch update --version 0.1.0-preview.31
# First installation: use dotnet tool install instead of update.
```

- Administration → Settings → AI Configuration lets each organization opt into read-only AI Help and configure its provider, exact model ID, approved endpoint, timeout and write-only API key. New and existing organizations default to disabled.
- Keys are protected on the server with organization-bound Data Protection purposes, never returned by the API, and cleared from the form after submission. Production requires the documented persistent, certificate-protected key ring. Revoke credentials previously exposed in chat or logs.
- DeepSeek, OpenAI, OpenAI-compatible and Ollama protocols are offered in the branded keyboard-accessible dropdown. Arbitrary endpoints are not accepted: the operator enrolls destinations and controls outbound networking. Additional Qwen/GLM presets and path support remain future work.
- The explicit connection test sends a small billable request to the saved provider without workspace data. Settings require management permission, version checks, antiforgery and organization isolation. Invalid tenant overrides never fall back to a platform credential.
- Forward platform migrations add organization settings and encrypted provider fields with forced PostgreSQL row-level security. Run the application's normal migrator; do not modify previously applied migrations.
- Shared compact floating inputs and the floating provider dropdown retain branding, 38 px standard controls and 34 px searches. Host forms and newly generated module text-like fields reuse the shared controls. Invitation stories verify that the selected role is submitted, not merely displayed.
- English/French documentation and installation commands are coordinated with this version. Storybook fixtures use fake credentials and providers, not paid services.

Local evidence and remaining limits are recorded in the shipped organization AI specification and the implementation PR. The complete Storybook inventory, automatically generated CRUD/workflow stories, full application-wide responsive matrix and real production-provider UAT remain outside this candidate. This preview is not an enterprise certification. The release pipeline must separately qualify the exact packages before publication.

Updating the installed template does not rewrite existing generated applications. Newly generated React projects include these changes; existing customized projects require reviewed source changes and forward migrations.

## Français

Candidat de préversion coordonnée CLI/template pour la configuration d’abonnement IA par organisation et les formulaires flottants partagés. La disponibilité exige la CI du commit exact sur main, la qualification scellée des deux paquets et la publication de confiance.

```bash
dotnet tool update --global Trykatch.Cli --version 0.1.0-preview.31
trykatch update --version 0.1.0-preview.31
```

Pour une première installation, utiliser `dotnet tool install`. Administration → Paramètres → Configuration IA permet à chaque organisation d’activer l’aide en lecture seule et de configurer fournisseur, modèle, destination approuvée, délai et clé API en écriture seule. L’activation est désactivée par défaut. Les clés sont protégées côté serveur par organisation, jamais renvoyées et effacées du formulaire après soumission. En production, conserver le trousseau Data Protection protégé par certificat conformément au guide. Révoquer toute clé exposée dans une conversation ou un journal.

La liste déroulante compacte et accessible propose DeepSeek, OpenAI, un protocole compatible OpenAI et Ollama. L’opérateur approuve les destinations ; les destinations arbitraires et les futurs préréglages Qwen/GLM ne sont pas inclus. Le test de connexion explicite peut être facturé et ne transmet aucune donnée métier. Autorisations, versions, antiforgery et isolation restent appliqués côté serveur, sans repli d’une configuration d’organisation invalide vers les clés de la plateforme.

Les migrations de plateforme sont additives et imposent la sécurité PostgreSQL par ligne. Utiliser le migrateur habituel, sans modifier les migrations appliquées. Les champs partagés conservent la marque et les tailles de 38 px (recherche 34 px) dans les formulaires hôtes et les nouveaux modules. Les stories d’invitation vérifient l’envoi du rôle choisi.

La couverture exhaustive de Storybook, les stories CRUD/workflow automatiques, la matrice complète de l’application et l’UAT avec un fournisseur réel restent hors de ce candidat. Ce n’est pas une certification entreprise. Mettre à jour le template ne réécrit pas les projets existants ; les projets personnalisés nécessitent des modifications revues et les migrations additives.
