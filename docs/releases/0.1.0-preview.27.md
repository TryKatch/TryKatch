# Trykatch 0.1.0-preview.27

## English

This preview delivers both agreed experiences in the template:

- Organization invitations support selecting an active, assignable role before sending. Acceptance uses the recorded role; the existing Member default remains for API callers that omit it. Permission-driven navigation hides administrative menus from ordinary members, with server-side management and delegation checks unchanged. Role details use friendly labels instead of dotted permission keys.
- AI Help supplies grounded getting-started guidance and documented next steps for users. Provider-returned read batches are fully validated and executed sequentially within the existing four-read total budget; writes, concurrent execution and automatic retries stay disabled.

- Developer onboarding stays available at generation time, with project-local coding-agent workflows, English/French guidance, starter questions and the first-feature backend/React walkthrough. Backend-only authentication guidance includes cookies, antiforgery and workspace selection.
- User-facing AI Help is included, with a bottom-corner chat launcher, an account-menu entry and the `/assistant` route. Enter sends, Shift+Enter adds a line, and sending clears the composer while preserving the question in the chat.
- The server-side, provider-neutral runtime uses `IChatClient` adapters for configurable Chat Completions (including DeepSeek), OpenAI Responses and Ollama. It is disabled by default; configure the API server's provider, model and credentials explicitly. Generation and startup do not make automatic hosted-model calls.
- Approved help guides explain architecture and module use; read-only workspace tools enforce current permissions and organization isolation. Answers are instructed to use the user's language and omit internal pagination fields unless specifically requested. No arbitrary source inspection, uploaded file contents or state-changing AI executor is included.
- Encrypted continuations support up to four completed exchanges for 20 minutes and are bound to the current actor, workspace, access and configuration. There is no durable conversation database or browser storage of conversation tokens. Starting a new chat resets context.
- Timeouts, per-instance request/concurrency limits, bounded tool/model payloads and provider response-limit errors fail safely, without automatic retry.
- Generated-package regression checks require the runtime, embedded help guides and both React entry points alongside developer onboarding, preventing the preview.26 omission from silently recurring.
- Workspace Recent activity owns its card/header/row spacing instead of depending on a removed grid wrapper. Long titles wrap and activity dots retain their size; English/French and small-screen layouts are verified separately from data correctness.

Publication requires successful exact-commit main CI and sealed tag qualification of the exact template/CLI package pair. Source tests alone do not prove published-package UAT. This remains a preview; the production-readiness plan's operational, governance, accessibility and independent acceptance gates remain open. The separate role-management UX branch is not included.

```bash
dotnet tool install --global Trykatch.Cli --version 0.1.0-preview.27
# Existing installation:
# dotnet tool update --global Trykatch.Cli --version 0.1.0-preview.27
dotnet new install Trykatch.Templates@0.1.0-preview.27
trykatch new MyApp
```

## Français

Les invitations permettent de choisir un rôle actif avant l’envoi. Les menus suivent les permissions effectives et les membres ordinaires n’accèdent pas à la gestion des utilisateurs. Les détails des rôles utilisent des libellés lisibles, sans identifiants techniques. L’aide IA explique les fonctionnalités documentées et propose les prochaines étapes ; les lectures groupées sont validées intégralement et exécutées séquentiellement, dans la limite existante de quatre lectures par question.

Cette version préliminaire livre les deux expériences convenues : l’accueil des développeurs et l’aide IA destinée aux utilisateurs de l’application. Les instructions de génération, les workflows des agents de programmation et le parcours première fonctionnalité backend/React restent inclus, y compris l’authentification du backend seul.

L’aide IA comprend le bouton de discussion flottant, l’entrée du menu du compte et la route `/assistant`. Entrée envoie le message ; Maj+Entrée ajoute une ligne. Le moteur serveur permet de choisir explicitement le fournisseur et le modèle, notamment DeepSeek via Chat Completions, OpenAI Responses ou Ollama. Il est désactivé par défaut et n’effectue aucun appel automatique au démarrage ou à la génération.

Les guides approuvés et les outils de consultation respectent les permissions et l’isolation des organisations. Les réponses suivent la langue de l’utilisateur et doivent masquer les champs de pagination internes sauf demande explicite. Les suites de conversation chiffrées permettent quatre échanges pendant 20 minutes, sans stockage durable ni exécution d’écriture par l’IA. Les limites et les erreurs du fournisseur ne déclenchent pas de nouvelle tentative automatique.

Les tests des paquets générés exigent le moteur, les guides intégrés et les deux entrées React en plus de l’accueil des développeurs. La publication dépend de la CI du commit exact sur main et de la qualification des paquets exacts. Cette version reste préliminaire : elle ne clôt pas les critères complets de préparation à la production. La branche distincte d’amélioration des rôles n’est pas incluse.

Le panneau d’activité récente possède désormais ses propres marges internes, sans dépendre d’une ancienne grille. Les titres longs passent à la ligne et les indicateurs conservent leur taille.
