# Trykatch 0.1.0-preview.29

## English

Coordinated CLI/template release candidate, not proof of publication. Retains the onboarding, provider-neutral AI Help and display-branding changes from preview.27/preview.28, and adds the branded Storybook workspace and validated compact floating forms.

```bash
dotnet tool update --global Trykatch.Cli --version 0.1.0-preview.29
trykatch update --version 0.1.0-preview.29
# First CLI installation: use dotnet tool install instead of update.
```

React-generated projects include an isolated Storybook 10.6 catalogue. From the application's `web` directory, run `corepack pnpm install --frozen-lockfile`, then `corepack pnpm storybook`. The catalogue does not need the backend, Docker or Aspire. Backend-only projects omit it.

- Floating input, textarea, password and search controls retain Trykatch branding, transparent border notches and associated accessible labels. Standard inputs are 38 px, search inputs 34 px; buttons keep their size.
- Optional inset search-filter dropdowns support caller-owned filters and DataTable integration. Columns remains separate at the trailing edge.
- Role, Projects and Documents metadata forms use Zod 4.5.4; corresponding backend requests use FluentValidation 12.1.1. Server permissions, file safety and domain invariants remain authoritative.
- Role-editor scrolling no longer overlaps its persistent footer. Validation and failed-save stories exercise preserved input.
- English/French documentation and shipped AI guidance require consulting Storybook for frontend work.

Local post-synchronization checks passed: 112 Chromium interaction/accessibility stories, workspace typecheck/unit tests and production/catalogue/docs builds; backend build with zero warnings/errors; 432 host, 2 Projects and 13 Documents unit tests; 12 host and 5 tests for each affected module's architecture. One unmatched Documents upload request was blocked and logged during passing story tests; passing tests do not establish every unexpected-request path fails its owning test.

Remaining roadmap items: checked inventory enforcement, remaining states/server pagination, automatic generated CRUD/workflow stories and rollback qualification, and the full responsive/theme/locale matrix. Updating the installed template does not rewrite existing generated applications.

Publication requires successful exact-commit main CI, sealed candidate qualification, and verified availability of both NuGet packages. This remains a preview, not an enterprise certification or proof that all production-readiness gates are closed.

## Français

Candidat de préversion coordonnée CLI/template, pas une preuve de publication. Conserve l’accueil des développeurs, l’aide IA indépendante du fournisseur et la marque d’affichage, puis ajoute Storybook 10.6 et les formulaires flottants validés.

Pour mettre à jour : `dotnet tool update --global Trykatch.Cli --version 0.1.0-preview.29`, puis `trykatch update --version 0.1.0-preview.29`. Pour une première installation, utiliser `dotnet tool install`.

Depuis `web` d’une application React générée, exécuter `corepack pnpm install --frozen-lockfile`, puis `corepack pnpm storybook`. Aucun backend, Docker ou Aspire n’est nécessaire pour le catalogue. Les projets backend-only n’incluent pas Storybook.

Les champs gardent la marque Trykatch, des libellés associés et transparents, une encoche réelle et une taille compacte (38 px, recherche 34 px). Les filtres restent contrôlés par la fonctionnalité ; Colonnes reste séparé à droite. Les métadonnées des rôles, projets et documents utilisent Zod 4.5.4 côté React et FluentValidation 12.1.1 côté backend ; les contrôles serveur restent obligatoires. Le dialogue des rôles garde un corps défilant et un pied fixe sans chevauchement.

Les contrôles locaux ci-dessus ont réussi ; un téléversement Documents non simulé a été bloqué et journalisé malgré la réussite des tests. La couverture exhaustive, les stories automatiques du générateur et la matrice complète restent à terminer. Mettre à jour le template ne réécrit pas les applications existantes. La publication exige la CI du commit exact sur main, la qualification scellée et la disponibilité vérifiée des deux paquets NuGet.
