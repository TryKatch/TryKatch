# Trykatch 0.1.0-preview.33

## English

Coordinated CLI/template preview candidate that makes a generated project's name its initial customer-facing brand. Availability requires successful exact-main CI, sealed qualification of the release package pair and trusted publication; candidate metadata does not prove publication.

```bash
dotnet tool update --global Trykatch.Cli --version 0.1.0-preview.33
trykatch update --version 0.1.0-preview.33
# First installation: use dotnet tool install instead of update.
```

- A project generated with `trykatch new Northstar.Portal` now displays `Northstar.Portal` on the sign-in page, authenticated navigation, invitation/activation surfaces, browser title and generated email branding.
- `--display-name "Northstar"` remains the explicit way to choose a friendlier customer-facing name independently of .NET namespaces and project paths.
- Packed-template regression coverage verifies default React, backend-only and quoted custom brands.
- The real sign-in unit test and Storybook interaction verify that the configured application name remains the visible home brand in English and French.
- CLI help plus English/French generated and public documentation describe the new default and later environment/configuration overrides.
- The generated-application landing-page boundary, organization AI settings, role selection, shared floating controls, Storybook coverage and security boundaries from preview.32 remain included.

The complete Storybook inventory, automatically generated CRUD/workflow stories, full application-wide responsive matrix, simultaneous authorization-revocation race proof and real production-provider UAT remain outside this candidate. This preview is not an enterprise certification. The release pipeline must separately qualify the exact packages before publication.

Updating the installed template does not rewrite existing generated applications. Newly generated projects include this default; existing applications can set `VITE_APPLICATION_NAME` and `Email:Branding:ApplicationName` or apply a reviewed source update.

## Français

Candidat de préversion coordonnée CLI/template qui utilise le nom d'un projet généré comme marque initiale destinée aux utilisateurs. La disponibilité exige la CI du commit exact sur main, la qualification scellée des deux paquets et la publication de confiance.

```bash
dotnet tool update --global Trykatch.Cli --version 0.1.0-preview.33
trykatch update --version 0.1.0-preview.33
```

Pour une première installation, utiliser `dotnet tool install` au lieu de `update`.

- Un projet généré avec `trykatch new Northstar.Portal` affiche désormais `Northstar.Portal` sur la page de connexion, la navigation authentifiée, les écrans d'invitation et d'activation, le titre du navigateur et la marque des e-mails générés.
- `--display-name "Northstar"` reste le moyen explicite de choisir une marque plus conviviale, indépendante des espaces de noms .NET et des chemins de projet.
- La régression sur le modèle empaqueté vérifie les marques par défaut des projets React et backend ainsi que les marques personnalisées contenant des guillemets.
- Le test réel de connexion et l'interaction Storybook vérifient que le nom configuré reste la marque d'accueil visible en anglais et en français.
- L'aide CLI et la documentation anglaise/française décrivent la nouvelle valeur par défaut et les remplacements ultérieurs par environnement ou configuration.
- La séparation de la landing page générée, la configuration IA par organisation, l'attribution des rôles, les champs flottants partagés, Storybook et les limites de sécurité de preview.32 restent inclus.

La couverture Storybook exhaustive, les stories CRUD/workflow automatiques, la matrice responsive complète, la preuve d'une course de révocation simultanée et l'UAT avec un fournisseur réel restent hors de ce candidat. Ce n'est pas une certification entreprise.

La mise à jour du template ne réécrit pas les applications existantes. Les nouveaux projets incluent cette valeur par défaut ; les applications existantes peuvent définir `VITE_APPLICATION_NAME` et `Email:Branding:ApplicationName` ou appliquer une mise à jour de source revue.
