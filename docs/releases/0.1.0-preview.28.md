# Trykatch 0.1.0-preview.28

## English

Coordinated preview target, not proof of publication. This candidate retains the developer onboarding, provider-neutral user-facing AI Help, invitation roles, branded HTML email and activity layout described in [preview.27](0.1.0-preview.27.md), and separates customer-facing branding from technical .NET project names.

```bash
dotnet tool install --global Trykatch.Cli --version 0.1.0-preview.28
# Existing installation:
# dotnet tool update --global Trykatch.Cli --version 0.1.0-preview.28
dotnet new install Trykatch.Templates@0.1.0-preview.28
trykatch new Kamenta.App --display-name "Kamenta" --email true
```

- `--display-name` defaults to Trykatch independently of the technical namespace. Names containing quotes are encoded as source string literals.
- Authentication, invitations, platform activation, shell brand marks and browser titles use the generated display brand. Later web overrides use `VITE_APPLICATION_NAME` at build/start time.
- Email subjects and HTML use the generated brand, with operator overrides through `Email:Branding:ApplicationName`. Mailpit's default sender follows the email brand; explicit `Email:From` values retain precedence. Existing captured messages are not rewritten.
- The packed generation regression checks cover full-stack and backend-only output and use a portable, canonicalized temporary directory for Ubuntu and macOS qualification.

Publication still requires successful exact-commit main CI and sealed tag qualification of the exact template/CLI package pair. Local branding, email and SMTP checks are not public-install UAT or production SMTP2GO delivery evidence. Production-readiness gates remain open; no authentication, authorization or tenant-isolation behavior changes in this branding fix.

## Français

Cible coordonnée de préversion, pas une preuve de publication. Cette version conserve l’accueil des développeurs, l’aide IA utilisateur indépendante du fournisseur, les rôles d’invitation, les e-mails HTML personnalisés et la mise en page de l’activité décrits dans [preview.27](0.1.0-preview.27.md).

`trykatch new Kamenta.App --display-name "Kamenta" --email true` conserve les espaces de noms techniques tout en affichant Kamenta. Le nom affiché utilise par défaut Trykatch. Les chaînes sont encodées ; la marque est centralisée dans les pages d’authentification, d’invitation, d’activation et de navigation ainsi que le titre du navigateur.

`VITE_APPLICATION_NAME` permet un remplacement à la compilation ou au démarrage web. `Email:Branding:ApplicationName` définit la marque des objets et du HTML des e-mails. L’expéditeur Mailpit suit cette marque par défaut ; `Email:From` explicite reste prioritaire. Les messages déjà capturés restent inchangés. Les contrôles du paquet couvrent les applications React et backend-only avec un répertoire temporaire portable.

La publication exige toujours la CI du commit exact sur main et la qualification scellée du tag pour les deux paquets. Les contrôles locaux ne prouvent ni l’installation publique ni la livraison SMTP2GO en production. Les critères de préparation à la production restent ouverts.
