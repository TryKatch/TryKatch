## Preflight rulings

- The accepted phase exit asks for an installed module event, not a new production business consumer. Use a clearly test-only effect module with a real installed Projects source; cost if insufficient is additional end-product acceptance later, not fictional product behavior.
- Use the real application use case/executor through a dedicated process host, not a new production host override or HTTP login harness. Evidence must state this layer; secured HTTP paths retain existing tests.
- Typed outbox currently requires an executable operation. Supply a real Projects user-command adapter instead of widening the framework with a provenance-only operation category. No placeholder handler.

- Public job submission intentionally accepts only current-user commands. Use a synthetic UserCommand for the separate restart job, with the committed-event consumer proving finite system authority; do not broaden scheduler authority or seed a supposed production system admission path. Cost if a scheduled-system process proof is later required is an additional recurring-target acceptance scenario.

- The actual two-process acceptance found both production Quartz nodes named the literal AUTO. The pinned4.6 XML and official Quartz4 guidance confirm typed GenerateInstanceId=true, unlike assigning InstanceId="AUTO". Correct this host adapter in the exit slice and retain distinct-node/membership assertions as the behavioral RED→GREEN regression; include directly affected scheduling checks. No scheduler dependency or schema change is required.
