## Prérequis

Installez le SDK .NET 10 et un runtime de conteneurs compatible avec Docker avant de démarrer une application générée. Utilisez Docker Desktop sous macOS ou Windows, ou Docker Engine sous Linux, puis vérifiez que le démon est disponible :

```bash
docker info
```

Docker est requis pour PostgreSQL et pour toute la chaîne d’observabilité locale : OpenTelemetry Collector, Prometheus, Loki, Tempo et Grafana. L’AppHost crée et coordonne ces conteneurs ; installer uniquement le client Docker ne suffit pas — le démon Docker doit être actif. Aspire 13.5 nécessite Docker CLI 25.0 ou une version ultérieure ; vérifiez donc aussi la version du client avec `docker version`.

Lorsque le stockage est activé (par défaut), Aspire démarre aussi MinIO pour les téléversements de documents locaux. Utilisez `--storage false` à la génération uniquement si vous ne souhaitez pas les adaptateurs de stockage ni MinIO. Preview.21 corrige la condition du template pour inclure réellement cette ressource dans l’AppHost généré ; une mise à jour de la CLI ne réécrit pas l’AppHost d’une application existante.

Pour une application React, installez aussi Node.js 24 et activez le relais pnpm de Corepack avec `corepack enable pnpm`. **Depuis le dossier de l’application générée**, `pnpm --version` et `corepack pnpm --version` doivent afficher la version fixée dans `package.json` (actuellement `10.17.1`). Aspire lance le `pnpm` trouvé dans son `PATH` ; une autre version globale ou fournie par un agent peut entrer en conflit avec les dépendances installées par Corepack. Si `web-installer` signale `ERR_PNPM_ABORTED_REMOVE_MODULES_DIR_NO_TTY`, arrêtez l’AppHost, corrigez l’exécutable pnpm dans le `PATH`, lancez `corepack pnpm --dir web install --frozen-lockfile` depuis la racine de l’application, puis relancez `trykatch start`. Ne modifiez pas la version du projet et ne forcez pas la suppression des dépendances pour masquer une incompatibilité de versions.

## Installer le modèle

Suivez ces étapes dans l’ordre.

### 1. Installer la CLI Trykatch

Exécutez cette commande une seule fois sur votre ordinateur :

```bash
dotnet tool install --global Trykatch.Cli --version 0.1.0-preview.26
```

Cette commande installe la commande `trykatch`. Elle n’installe pas encore le modèle de projet.

### 2. Installer le modèle de projet

Lorsque l’étape 1 a réussi, exécutez :

```bash
trykatch template install
```

Cette commande installe le modèle .NET et React correspondant. Elle utilise le moteur de modèles officiel de Microsoft, affiche une progression animée dans un terminal interactif et produit des lignes de journal stables dans la CI.

Vous pouvez relancer cette commande sans risque. Si cette version exacte est déjà présente, elle l’indique et se termine avec succès. Si une version antérieure est présente, le moteur de modèles .NET la met à jour.

### 3. Créer votre application

Remplacez `Horizon` par le nom de votre produit :

```bash
trykatch new Horizon
cd Horizon
```

La création affiche un indicateur animé, le numéro de l’étape et le temps écoulé pendant la validation des options et la génération du template avec l’initialisation Git. Les messages du moteur de templates apparaissent après l’arrêt de l’indicateur. Une sortie redirigée ou `TERM=dumb` utilise des lignes simples. Les échecs portent la mention `FAIL` et conservent les détails du diagnostic. Les conflits avec des fichiers existants affichent un message concis plutôt que des centaines de lignes ; ajoutez `--verbose` pour voir les détails complets. Contrairement à la génération atomique d’un module, une création de projet interrompue peut laisser des fichiers partiels : vérifiez le dossier de sortie avant de réessayer ; Trykatch ne supprime pas un dossier existant pour récupérer.

La commande `trykatch new` génère l’application et l’initialise comme dépôt Git
avec `main` comme branche initiale. Si le répertoire de sortie se trouve déjà
dans un dépôt Git, Trykatch conserve le dépôt parent au lieu de créer un dépôt
imbriqué.

:::note[Alternative : installer sans la CLI Trykatch]
Si vous ne souhaitez pas utiliser la CLI Trykatch avec progression, utilisez la commande suivante **à la place des étapes 1 et 2** :

```bash
dotnet new install Trykatch.Templates@0.1.0-preview.26
dotnet new trykatch -n Horizon --allow-scripts yes
```

`--allow-scripts yes` autorise l’action d’initialisation Git fournie avec le
modèle. Sans cette option, le moteur de modèles .NET demande une confirmation
interactive.
:::

Les noms contenant des points ou des tirets sont normalisés pour produire des espaces de noms C#, des répertoires, des noms de conteneurs et des packages npm valides.

## Mettre à jour le modèle

Mettez d’abord à jour la CLI, puis utilisez la commande de mise à jour dédiée de Trykatch. La CLI et le modèle restent ainsi sur la même version :

```bash
dotnet tool update --global Trykatch.Cli --version 0.1.0-preview.26
trykatch update
```

`trykatch template update` est l’équivalent explicite. Ajoutez `--version <version>` à l’une ou l’autre commande pour sélectionner une version précise.

Si cette version exacte du modèle est déjà installée, la mise à jour réussit sans rien modifier. Trykatch indique qu’aucune mise à jour n’est nécessaire et ne supprime ni ne réinstalle le modèle opérationnel. Utilisez `--force` uniquement pour réparer volontairement cette même version en la réinstallant.

La mise à jour du modèle s’applique aux futurs projets générés ; elle ne réécrit pas les fichiers source d’une application existante.

### Si un téléchargement NuGet est interrompu

Lorsque NuGet signale une fin de flux inattendue (EOF) ou un flux de transport vide, Trykatch regroupe les messages répétés du SDK en une seule erreur exploitable. Réessayez d’abord exactement la commande affichée par la CLI. Si vous aviez lancé une réparation explicite avec `--force`, la commande de nouvelle tentative conserve aussi `--force` afin de ne pas devenir une mise à jour ordinaire sans effet. Si le téléchargement échoue encore, videz uniquement le cache HTTP de NuGet, puis relancez la mise à jour :

```bash
dotnet nuget locals http-cache --clear
trykatch update --version 0.1.0-preview.26
```

Le moteur de modèles .NET peut supprimer l’ancienne version avant la fin d’une mise à jour forcée. Relancer la commande Trykatch restaure le modèle ; les applications déjà générées ne sont pas affectées.

## Désinstaller Trykatch

Supprimez d’abord le modèle de projet, pendant que la CLI Trykatch est encore disponible :

```bash
trykatch template uninstall
```

Si vous avez installé le modèle sans la CLI Trykatch, utilisez la commande Microsoft équivalente : `dotnet new uninstall Trykatch.Templates`.

Pour supprimer également la CLI de votre ordinateur, exécutez :

```bash
dotnet tool uninstall --global Trykatch.Cli
```

La désinstallation du modèle ou de la CLI ne supprime pas les applications déjà générées.

## Réparer les certificats HTTPS locaux

L’AppHost sécurise son tableau de bord et son service de ressources interne avec le certificat de développement ASP.NET Core. Si Aspire signale une erreur de nom de certificat, de confiance ou de TLS sur un poste de développement, arrêtez l’AppHost puis recréez le certificat local :

```bash
dotnet dev-certs https --clean
dotnet dev-certs https --trust
```

Redémarrez ensuite l’AppHost. Trykatch fixe chaque point de terminaison Aspire généré sur `https://localhost` afin que son nom corresponde au certificat.

## Choisir l’interface générée

React est inclus par défaut. Ne générez une solution limitée au backend que lorsque ce choix est intentionnel :

```bash
trykatch new Horizon --ui none
```

Les modules gratuits optionnels sont désactivés par défaut :

```bash
trykatch new Horizon \
  --email true \
  --storage true \
  --documents true \
  --images true
```

## Découvrir les commandes disponibles

Utilisez les commandes d’aide ciblées de la CLI :

```bash
trykatch help
trykatch start --help
trykatch update
trykatch template help
trykatch module help
```

`trykatch help` présente les choix de génération d’application. `trykatch start --help` documente le démarrage. `trykatch template help` documente l’installation, la mise à jour et la suppression du modèle. `trykatch module help` répertorie toutes les commandes prises en charge pour le cycle de vie des modules.

## Exécuter le backend et le frontend

Avant le premier démarrage, depuis la racine de l’application :

```bash
trykatch setup
trykatch doctor
trykatch start
```

`setup` restaure les dépendances .NET verrouillées et les dépendances frontend épinglées, sans modifier les secrets, certificats ni bases de données. Les applications backend-only ignorent Node et pnpm. `doctor` contrôle le SDK, les versions pnpm de Corepack et du PATH, la présence du certificat, Docker et les modules ; il explique les corrections sans les appliquer. Corepack peut télécharger son outil épinglé dans son cache. La confiance du certificat reste une étape manuelle.

Après le démarrage, `trykatch status --api-url <origine API affichée par Aspire>` vérifie les endpoints live et ready. L’origine doit être HTTP(S) en boucle locale ; la vérification du certificat reste active. Sans URL, status décrit la configuration et indique que la santé runtime est inconnue. Chaque commande accepte `--root` ; un contrôle en échec retourne le code 2.

Gardez Docker actif. Depuis la racine de l’application générée, cette commande unique démarre **à la fois le backend ASP.NET Core et le frontend React**, avec PostgreSQL, les migrations, OpenTelemetry et les services d’observabilité locaux :

La racine de l’application est le répertoire créé par `trykatch new`, par exemple `Horizon/`. Il contient `Horizon.slnx`, `src/`, `tests/` et `web/`. Placez-vous dans ce répertoire avant toute commande de restauration, compilation, test, pnpm ou démarrage :

```bash
cd /chemin/vers/Horizon
trykatch start
```

Démarrez toujours l’AppHost — jamais le projet API seul — car Aspire fournit la base de données et les identifiants d’exécution requis par le backend.

## Examiner le backend

Après le démarrage de l’AppHost, ouvrez le tableau de bord Aspire et sélectionnez la ressource **api**. Utilisez son URL HTTPS comme `<URL API>` ci-dessous :

- `<URL API>/health/live` confirme que le processus API est actif.
- `<URL API>/health/ready` confirme que l’API et ses dépendances requises sont prêtes.
- `<URL API>/docs` ouvre la référence API interactive Scalar en environnement Development.
- `<URL API>/openapi/v1.json` renvoie le document OpenAPI en environnement Development.

Trykatch utilise Scalar plutôt que Swagger UI. Lorsque l’API est lancée directement avec son profil HTTPS versionné, `<URL API>` vaut `https://localhost:7268`. Le démarrage par l’AppHost reste recommandé, car Aspire fournit PostgreSQL et les chaînes de connexion d’exécution.

### Si l’application React signale un client généré manquant

Les modèles actuels incluent le client généré et le vérifient lors de la création du paquet. La commande de développement répare également un client manquant avant le démarrage de Vite. Pour un projet créé avec une ancienne préversion, effectuez la réparation une fois, puis revenez à la racine de l’application et démarrez l’application Aspire complète :

```bash
cd /chemin/vers/Horizon/web
corepack pnpm install --frozen-lockfile
corepack pnpm generate
cd ..
trykatch start
```

N’exécutez pas `corepack pnpm dev` depuis la racine de la solution : l’espace de travail pnpm et son script `dev` se trouvent dans `web`. Cette commande lancée depuis `web` démarre volontairement uniquement le serveur de développement React ; utilisez `trykatch start` lorsque l’authentification, PostgreSQL, les migrations, l’API et l’observabilité sont nécessaires.

### Si Aspire affiche « Container runtime unhealthy »

Vérifiez que le démon Docker — et pas uniquement l’application Docker — est prêt :

```bash
docker info
docker version
```

Si `docker info` échoue, redémarrez Docker Desktop et attendez que son moteur soit opérationnel. Réactivez le moteur si Docker Resource Saver l’a suspendu. Si `docker version` indique un client antérieur à la version 25.0, mettez Docker Desktop à jour et vérifiez que Rider ou votre terminal utilise bien le nouvel exécutable `docker`. Arrêtez ensuite l’AppHost, puis redémarrez-le.

La fenêtre Docker Desktop peut afficher **Engine running** alors qu’un terminal attend encore le socket du démon ou utilise un autre contexte Docker. Exécutez `docker context show` et `docker version` dans le même terminal que `trykatch start`. La CLI respecte désormais la fenêtre normale de réveil du mode Resource Saver avant de signaler un échec.

Les modèles actuels attribuent au volume PostgreSQL persistant de développement un mot de passe administrateur local explicite. La recréation d’une application portant le même nom conserve donc les mêmes identifiants de base de données. Si un projet créé avec une ancienne préversion affiche immédiatement `password authentication failed for user "postgres"` après que vous avez volontairement supprimé puis régénéré cette application, arrêtez d’abord l’AppHost. Si, et seulement si, l’ancienne base locale est jetable, supprimez le volume exact de cette application (par exemple `docker volume rm horizon-postgres-data`), puis redémarrez. La suppression du volume détruit définitivement cette base locale ; conservez-la ou sauvegardez-la si ses données sont importantes.

PostgreSQL et les conteneurs d’observabilité locale ne peuvent pas démarrer lorsque le runtime de conteneurs est défaillant ; les ressources dépendantes restent donc correctement dans l’état **Waiting**. Le **migrateur** est un processus ponctuel : l’état **Finished** avec le code de sortie 0 indique un succès, pas une application arrêtée. Les ressources **api** et **web** doivent ensuite passer à l’état actif. Examinez la première ressource en échec ou défaillante au lieu de redémarrer chaque ressource séparément.

## Installation du modèle dans l’IDE

Le package utilise le moteur de modèles standard de .NET. Rider peut installer le fichier `.nupkg` depuis **New Solution → More Templates → Install Template**. Après l’installation, Visual Studio découvre les modèles du SDK dans **Create a new project** ; recherchez **Trykatch**.

:::caution[État de préversion]
Trykatch est une préversion orientée production, pas une certification de mise en production. Chaque produit généré doit effectuer sa propre qualification de sécurité, de restauration, de capacité et d’exploitation.
:::
