## Prerequisites

Install the .NET 10 SDK and a Docker-compatible container runtime before starting a generated application. Use Docker Desktop on macOS or Windows, or Docker Engine on Linux, and confirm that the daemon is available:

```bash
docker info
```

Docker is required for PostgreSQL and the complete local observability pipeline: the OpenTelemetry Collector, Prometheus, Loki, Tempo, and Grafana. The AppHost creates and coordinates these containers; installing only the Docker client is not sufficient—the Docker daemon must be running.

## Install the template

Follow these steps in order.

### 1. Install the Trykatch CLI

Run this once on your computer:

```bash
dotnet tool install --global Trykatch.Cli --version 0.1.0-preview.12
```

This installs the `trykatch` command. It does not install the project template yet.

### 2. Install the project template

After Step 1 succeeds, run:

```bash
trykatch template install
```

This installs the matching .NET and React template. The command uses Microsoft's official .NET template engine, displays live progress in an interactive terminal, and emits stable log lines in CI.

The command is safe to run again. If this exact version is present, it reports that the template is already installed and exits successfully. If an older version is present, the .NET template engine updates it.

### 3. Create your application

Replace `Horizon` with your product name:

```bash
trykatch new Horizon
cd Horizon
```

The `trykatch new` command generates the application and initializes it as a Git
repository with `main` as its initial branch. If the output directory is already
inside a Git worktree, Trykatch preserves the parent repository instead of
creating a nested one.

:::note[Alternative: install without the Trykatch CLI]
If you do not want the progress-aware Trykatch CLI, use the following command **instead of Steps 1 and 2**:

```bash
dotnet new install Trykatch.Templates@0.1.0-preview.12
dotnet new trykatch -n Horizon --allow-scripts yes
```

`--allow-scripts yes` authorizes the template’s packaged Git initialization
action. Without it, the .NET template engine asks for confirmation interactively.
:::

React is the default surface. The generated project contains the complete `web` workspace, including the React application, reusable UI and module packages, generated API client, tests, lockfile, and production container.

Names containing dots and hyphens are normalized for C# namespaces, directories, container names, and npm packages.

## Update the template

Update the CLI first, then use the dedicated Trykatch update command. This keeps the CLI and template on the same release:

```bash
dotnet tool update --global Trykatch.Cli --version 0.1.0-preview.12
trykatch update
```

`trykatch template update` is the explicit equivalent. Use `--version <version>` with either command when you need a particular release.

Template updates affect projects generated in the future; they do not rewrite an existing application's source files.

## Uninstall Trykatch

Remove the project template first, while the Trykatch CLI is still available:

```bash
trykatch template uninstall
```

If you installed the template without the Trykatch CLI, use the equivalent Microsoft command: `dotnet new uninstall Trykatch.Templates`.

If you also want to remove the CLI from your computer, run:

```bash
dotnet tool uninstall --global Trykatch.Cli
```

Uninstalling the template or CLI does not delete applications you already generated.

## Repair local HTTPS certificates

The AppHost secures its dashboard and internal resource service with the ASP.NET Core development certificate. If Aspire reports a certificate name, trust, or TLS error on a development computer, stop the AppHost and recreate the local certificate:

```bash
dotnet dev-certs https --clean
dotnet dev-certs https --trust
```

Then restart the AppHost. Trykatch pins every generated Aspire endpoint to `https://localhost` so the endpoint name matches that certificate.

## Choose the generated surface

React is included by default. Generate a backend-only solution only when that is intentional:

```bash
trykatch new Horizon --ui none
```

Optional free modules are disabled by default:

```bash
trykatch new Horizon \
  --email true \
  --storage true \
  --documents true \
  --images true
```

## Explore available commands

Use the CLI's focused help commands:

```bash
trykatch help
trykatch start --help
trykatch update
trykatch template help
trykatch module help
```

`trykatch help` lists application-generation choices. `trykatch start --help` documents application startup. `trykatch template help` documents template installation, updates, and removal. `trykatch module help` lists every supported module lifecycle command.

## Start the application

Keep Docker running. Always start the AppHost—not the API project by itself—so PostgreSQL, migrations, runtime credentials, the API, React, OpenTelemetry, and the observability services start together.

<Tabs syncKey="start-method">
  <TabItem label="CLI" icon="terminal">
    From the generated application's root directory, run:

    ```bash
    trykatch start
    ```

    The CLI discovers the generated AppHost. From another directory, use `trykatch start --root /path/to/Horizon`.
  </TabItem>
  <TabItem label="Rider">
    Open the generated `Horizon.slnx` file and allow Rider to restore the solution. Select **`Horizon.AppHost: https`** in the run-configuration menu, then choose **Run** or **Debug**.

    If Rider has not created the configuration, right-click `src/Horizon.AppHost/Horizon.AppHost.csproj` and choose **Run 'Horizon.AppHost'** once.
  </TabItem>
  <TabItem label="Visual Studio">
    Open `Horizon.slnx`. In Solution Explorer, right-click **Horizon.AppHost**, choose **Set as Startup Project**, select the **https** launch profile, and press **F5** or choose **Start**.
  </TabItem>
</Tabs>

The equivalent direct .NET command is `dotnet run --launch-profile https --project src/Horizon.AppHost/Horizon.AppHost.csproj`.

## Inspect the backend

After the AppHost starts, open the Aspire dashboard and select the **api** resource. Use its HTTPS URL as `<API URL>` below:

- `<API URL>/health/live` confirms that the API process is alive.
- `<API URL>/health/ready` confirms that the API and its required dependencies are ready.
- `<API URL>/docs` opens the interactive Scalar API reference in Development.
- `<API URL>/openapi/v1.json` returns the OpenAPI document in Development.

Trykatch uses Scalar rather than Swagger UI. When running the API directly with its checked-in HTTPS launch profile, `<API URL>` is `https://localhost:7268`; starting the AppHost remains the recommended workflow because Aspire supplies PostgreSQL and the runtime connection strings.

### If the React application reports a missing generated client

Current templates include the generated client and verify it during packaging. The development command also repairs a missing client before Vite starts. For a project generated by an older preview, repair it once, then return to the application root and start the complete Aspire application:

```bash
cd /path/to/Horizon/web
corepack pnpm install --frozen-lockfile
corepack pnpm generate
cd ..
trykatch start
```

Do not run `corepack pnpm dev` from the solution root: the pnpm workspace and its `dev` script live under `web`. Running it inside `web` intentionally starts only the React development server; use `trykatch start` when authentication, PostgreSQL, migrations, the API, and observability are required.

### If Aspire reports “Container runtime unhealthy”

Confirm that the Docker daemon—not only the Docker application—is ready:

```bash
docker info
```

If that command fails, restart Docker Desktop and wait until its engine is running. Resume the engine if Docker Resource Saver paused it. Then stop and restart the AppHost. PostgreSQL and the local observability containers cannot start while the container runtime is unhealthy, so the migrator and API correctly remain in **Waiting** and Grafana, Loki, Tempo, Prometheus, and the OpenTelemetry Collector report **Runtime unhealthy**.

## IDE template installation

The package uses the standard .NET template engine. Rider can install the `.nupkg` from **New Solution → More Templates → Install Template**. Visual Studio discovers installed SDK templates in **Create a new project** after the package is installed; search for **Trykatch**.

:::caution[Pre-release status]
Trykatch is a production-oriented preview, not a stable production certification. Every generated product must complete its own security, recovery, capacity, and operational qualification.
:::
