# E5 queued email implementation evidence

Status: In progress. The transport, protection, delivery policy, owned schemas, owned lease stores, explicit module metadata/registry, organization and Identity admission/preparation, and dispatcher components below have been implemented and checked. Complete host composition, caller migration, operational surfaces and final qualification remain incomplete.

## Baseline and scope

Work began in a fresh isolated worktree from `origin/develop` at `b932b087a9dfe57d286f4cb4c9aeb75a1d06b2d1`, the merged E4 PR #131 tree. The full parity roadmap and Phase 1 exits remain required. See the [E5 specification](../queued-email.md).

Strict locked restore of the integration project and its references passed. The initial `SmtpTransportTests` baseline passed 17 cases with zero skips. No dependency, live database, external email provider or deployed application was changed.

## Transport checkpoint

The internal SMTP transport now returns an allowlisted disposition, stage, failure code and optional numeric SMTP status. It distinguishes acknowledged, retryable, permanent and uncertain outcomes without returning remote replies, message bodies, addresses, credentials or original exceptions. Existing `IEmailSender` remains synchronous and exposes the existing sanitized `EmailDeliveryException` for unsuccessful results. The existing invitation and recovery notifier contracts remain unchanged.

Real loopback SMTP checks verify transient/permanent recipient rejection, lost final acknowledgement, cancellation before transmission, acknowledgement during connection reset, and bounded cleanup cancellation. Existing TLS, authentication and production configuration checks remain selected. Missing STARTTLS support is permanent rather than a blind retry. Successful `SendAsync` is acknowledged before disconnect cleanup, and cleanup honors the caller's total attempt cancellation budget.

The initial dropped-QUIT experiment did not reproduce a legacy failure with the locked MailKit 4.17.0; it is not evidence of an existing cleanup bug. A deterministic held-QUIT test waits until the server sees QUIT, then cancels the caller and requires prompt acknowledged completion. Deliberately replacing the cleanup cancellation token with `CancellationToken.None` made this test fail with `TimeoutException`; restoring the token passed. The reset fixture also waits for QUIT rather than sleeping after DATA acknowledgement.

The final targeted Release SMTP filter passed **23 cases, zero failures/skips**. After the deliberate regression and restoration, the single cleanup-budget case passed again. SMTP was confined to the loopback fixture; no real external email was sent.

## Protection checkpoint

Application defines a provider-neutral protected-payload seam and immutable protection context. The Infrastructure adapter uses the existing host Data Protection provider with purposes bound to format version, organization/Identity boundary, owner ID, delivery ID and template/version. Invalid or empty ownership context is rejected.

Three focused tests verify round-trip content, absence of plaintext recipient/token in the protected string, and cryptographic rejection when changing boundary, owner, delivery or template/version. The initial test failed to compile because the seam did not exist; the implemented adapter then passed. The combined Release protection and existing invitation-template filter passed **15 cases, zero failures/skips**: three new protection cases and 12 existing invitation-template compatibility cases. This verifies the primitive; actual queue-row protection, key rotation across delivery processes and final DI composition remain pending.

## Owned schema and lease checkpoint

Application now defines transport-neutral lease, preparation and completion contracts. One bounded policy permits five attempts, exponential retry delays starting at five seconds, a two-minute lease and a 45-second whole-attempt budget. Contradictory acknowledgement/status combinations are rejected; default diagnostic text for prepared messages, protected leases and reset intents omits private content. The focused policy/protection/access-profile filter passed **14 cases, zero failures/skips**, after the missing ownership declarations, missing organization mapping and inconsistent SMTP status tests failed first.

The additive Identity and Application migrations create `identity.email_deliveries` and `infrastructure.email_deliveries`. Both contain bounded operational metadata and protected-intent storage, with no recipient/token plaintext columns, foreign-key cascade or deletion policy. Mapping and schema declarations remain outside optional SMTP code so disabling email retains migration/history inspection. Identity receives SELECT/INSERT/UPDATE only; organization runtime receives scoped INSERT only on its relation; the coordinator receives SELECT/UPDATE only on that organization relation. Other runtime roles receive no access. Both allocations are reserved before generic schema grants. Organization delivery uses ENABLE/FORCE RLS with exact organization/actor append and coordinator policies.

The actual migrator passed on a fresh database, on a second idempotent invocation and on a database first migrated through E4. Existing Identity data survived the forward upgrade. Tests exercise all five role profiles, actual Identity lease operations under the narrow Identity runtime role, missing/mismatched organization and actor scope, and transaction rollback. Application, Platform and Identity snapshots match their current production models without opening a database. The affected inspection/migration run passed 34 of 35 cases; its sole failure was an existing custom-Identity-role fixture missing the new exact queue grant. That fixture was corrected without weakening inspection and the failed case passed separately. Together with the separately selected snapshot case, **36 distinct migration/inspection cases pass, zero skips**.

Identity queue mechanics use a dedicated context without an EF retry strategy. Each claim commits before exposing a lease; an uncertain commit can recover only the same assigned lease IDs, in a fresh context after disposal of the original transaction, with a five-second recovery budget. Completion uses delivery/owner/template/attempt/lease compare-and-set and retains the completed lease outcome for idempotent acknowledgement. Expired exhausted leases are terminalized in an ordered, limited `SKIP LOCKED` batch. Focused real-PostgreSQL mechanics passed **five cases, zero failures/skips**. Regressions first demonstrated unbounded cleanup and blocking on a locked exhausted row; both pass after correction. A post-commit transaction interceptor verifies exact committed-lease recovery. Those mechanics fixtures use disposable owner-backed `EnsureCreated`; the separate actual-migrator/runtime-role test supplies production schema/grant evidence. They do not establish token validation, protected queue admission, or an end-to-end SMTP guarantee.

Scaffolding used the pinned EF tool and an ignored design-only host; its final restore imports the application's central security pins and passes without advisory exceptions. No dependency lock, deployed database or external provider changed. This remains an implementation checkpoint, without the final integrated E5 review or PR qualification.

## Approved registration and preparation checkpoint

The public `IModuleEmailQueue` contract returns the frozen `Task<ModuleWorkReceipt>`. Template, source-policy and producer references are independently owned and versioned. Runtime catalog and ModuleTool manifest validation require finite declarations, owned source resources, registered user permissions, bounded template data and qualified storage keys, exact installed versions, and reciprocal system producer/policy consent. Email policy grants do not widen E2 business-resource grants. Reciprocal references to absent contributors may remain dormant. The compiled registry requires one explicit adapter for each installed declaration and renders synthetic previews separately from canonical current-source data. These declarations alone confer no runtime authority; organization admission and retry authorization still need implementation.

Malformed manifest collection entries first reproduced null-reference crashes. The CLI now returns validation errors instead. The final targeted Release unit selection passed **76 cases, zero failures/skips**, covering email contracts, registry, dispatcher, existing execution contracts and execution manifests (including the new email cases). No full unit suite was run.

The organization store now supports exact organization/admission lookup, bounded competing claims and exhausted cleanup, exact post-commit lease recovery, and conditional idempotent completion without INSERT/DELETE authority. Its internal retained `MessageId` column represents the logical dedup ID; the caller message ID remains a separate protected-intent requirement. Six owner-backed real-PostgreSQL mechanics cases passed with zero failures/skips. These fixtures do not qualify the new store's production coordinator-role composition or transactional admission.

Identity admission protects the original reset intent, handles exact-ID duplicates/conflicts, and validates the current confirmed recipient, suspension state, configured token provider and approved reset origin/query. Preparation reloads current Identity state with `AsNoTracking`, rechecks the original token rather than generating one, validates lease/ciphertext/ownership, and renders current permitted values. Separate-context changes reproduce and guard against stale tracked users. Nine real-PostgreSQL cases passed with zero failures/skips, using the actual Identity migrations and token provider. Test Data Protection keys are explicitly ephemeral. Uncertain insertion uses a bounded exact-ID read and reports unavailability if its result cannot be proven; fault-injection coverage for that path and actual runtime-role/HTTP/SMTP composition remain pending.

Password resets use a shared branded rendering path for queued preparation and the existing synchronous notifier. Explicit renderer DI preserves legacy output and encodes dynamic HTML. Message diagnostics redact recipient/body values. The renderer and existing invitation compatibility filter passed **14 cases, zero failures/skips**, after two new regressions failed with the renderer absent and the original message diagnostic text.

The dispatcher resolves fresh scoped sources and transport, requests at most one lease per source, prepares before SMTP, applies a bounded whole-attempt timeout and reserves five seconds before lease expiry for completion. Completion uses an independent bounded token after acknowledgement or caller cancellation and retries only the exact lease/outcome after a transient recording failure. Closed metrics carry boundary/outcome labels. Unexpected adapter defects stop the hosted worker with a sanitized exception, without retaining the original private message, inner exception or data. Three regressions first demonstrated missing completion headroom and private exception propagation; all pass in the 76-case selection. The dispatcher/worker are not yet registered as active host services. This verifies component behavior, not end-to-end delivery or comprehensive log privacy.

## Organization admission and current-source checkpoint

Organization submission appends to the active, non-retrying organization business transaction under the organization runtime role. It does not send or commit. A transaction advisory lock serializes the organization/authority/template/logical-dedup scope; a scoped pending-intent cache handles identical submissions before that transaction commits. Committed duplicates are read through the coordinator store only after current authorization and disclosure succeed. Changed immutable intent rejects without returning the old delivery ID. The protected versioned packet retains caller message ID separately from logical dedup ID, original selectors/data, admitted recipient, and host execution provenance. Its ownership/admission/template metadata must match the current row before preparation.

User admission and every retry recheck current membership, declared permissions, active organization and supported placement. System submission consumes the host-only E2 execution context and repeats current finite grant, exact email-policy allowance and reciprocal producer/template consent. Committed-event provenance also requires the current source event and compatible installed consumer metadata. Origin membership is not substituted for execution authority. The current source adapter constructs canonical permitted recipient and template data; caller JSON is never blindly merged into the rendered result. Changed recipient, missing module/template or revoked grant suppresses the message. Preparation uses a fresh organization-role transaction and disposes it before SMTP.

The initial missing source type produced a failing compile. The first targeted Release PostgreSQL selection then passed **six cases, zero failures/skips**, using actual migrations, ownership provisioning and narrow runtime connections: pending/committed duplicates, conflicting caller identity, protected storage, business/queue rollback, membership reauthorization, source revocation, current canonical rendering, tampered lease and scheduled system admission without a fabricated membership. A further targeted selection passed **seven cases, zero failures/skips**: competing admission, rejection of a system scope without host execution provenance, committed-event admission after origin membership revocation, current module/grant changes, and two real loopback TLS SMTP retry cases. A 450 rejection remains queued; the permitted retry sends current source data and records delivered, while revocation before retry records suppression without a second transport call or private body. A `pg_stat_activity` assertion observes no organization runtime transaction during each actual SMTP call. No external provider is used.

The Identity insertion recovery path now has **two additional real-PostgreSQL fault cases, zero failures/skips**. A command interceptor demonstrably throws after autocommit INSERT execution: one attempted insert persists one exact-ID row and returns accepted through bounded read recovery. A pre-execution fault reports unavailability with no row and no automatic insert retry; only a later explicit same-ID caller submission inserts it.

These tests compose the components through explicit fixture registrations. They do not establish production API/worker wiring, durable cross-process key continuity, complete invitation behavior, optional generated outputs, comprehensive log privacy or Phase 1 process-restart/real-module-event exits. The runtime organization source is not yet registered by the production email module.

An additional actual-role PostgreSQL case injects an `IOException` only after the outer organization transaction commits. A fresh caller submission with the same immutable logical identity returns the original delivery ID, with one retained row. The rollback case now includes a required audit intent alongside business and email writes. The eight-case selection passed seven cases (including six existing execution/scheduler/model regressions); its only failure was a fixture audit detail named `outcome`, rejected by the existing audit allowlist before enqueue. The fixture now uses the approved `status` key, and that failed case passes separately. No audit validation was relaxed. Together, **14 distinct organization queue cases and six affected existing execution cases pass, zero skips**.

## Identity hosting and closed fallback checkpoint

Identity now composes its queue only in an email-enabled runtime with an explicit nonblank `trykatch-identity` connection. Its dedicated singleton queue options do not enable EF retries; its scoped submission and source share one implementation. Normal Identity context retry/fallback behavior is unchanged. Missing named configuration and OpenAPI generation register only a closed unavailable submission. The configuration flag follows the global approved-link policy, without querying an account. Four focused hosting cases pass without database or SMTP connections, including missing-connection no-fallback, OpenAPI exclusion, invalid public origin, named connection and scoped identity. Their key provider is explicitly ephemeral. The email-disabled hosting case is conditional source coverage for subsequent packed-output qualification, not a claimed executed check.

The email module explicitly resolves payload protection through the host's shared Data Protection provider. A missing-registration regression failed first; the four-case protection filter then passed, including primitive purpose checks and DI with a shared ephemeral provider. Identity's existing host key-ring configuration remains authoritative; no independent queue key ring is introduced. Three directly affected existing SMTP transport-mode cases also pass after this DI addition. The dependency-free module fallback is registered when no active queue is composed and returns only an empty-ID unavailable receipt. Three focused fallback cases pass, including caller cancellation and resolution without database/SMTP access. These registrations do not start a dispatcher, migrate public recovery, or qualify the generated email-disabled output.
