## S1 — Scoped organization cache

The implementation follows the frozen cache contract in [feature parity contracts, section 7](../feature-parity-contracts.md#7-cache-and-realtime--s1s2): modules provide a bounded `ModuleCacheKey` and factory through `IOrganizationCache`; the host adds application, environment, organization, and audience identity. Current permission checks remain ahead of cache access. Cache values are detached DTO payloads; permission, membership, session, token, and other authority decisions are not cached.

The application dependency graph pins HybridCache 10.11.0 and Microsoft.Extensions.Caching.StackExchangeRedis 10.0.13, including the required `Microsoft.Extensions.DependencyInjection.Abstractions` 10.0.13 alignment. Normal and locked restores passed; the full vulnerability audit covered 36 projects with no findings, and the ten newly resolved package/version pairs were all permitted MIT. The isolated dependency gate separately built the pinned packages with no warnings/errors and exercised Valkey 9.1.2 at the pinned image digest, including cache operations, expiry, coalescing, fresh-provider L2 reads, and same-client outage/recovery. This library-level gate is separate from the application-host tests below; normal and locked solution restore also pass after the test-support project reference update; no external package version changed in that update.

PostgreSQL remains authoritative for invalidation. A host-owned organization cache generation is read in the current organization scope on every eligible cache read. Invalidation records the generation in the same transaction as the business write, including while cache reads are disabled. Local removal is registered for post-commit execution; peer L1s discover the changed generation on their next read. A cache outage falls back to the source, while a source exception remains an exception. Eligible cache hits therefore still cost one indexed PostgreSQL generation lookup. Old physical keys expire by TTL; generation rows must not be reset to their initial sentinel while old entries can remain.

The change adds an explicit READ ONLY, ReadCommitted organization scope for safe reads. The selected Projects detail route opts into it after its existing authorization; list and mutation routes retain their existing behavior. Ordinary write scopes, unsupported transactions, and pre-existing tracked entities in either shared context bypass shared caching; detected source mutations decline publication. Unsupported mapped/entity object graphs are rejected rather than stored. See the [read-scope integration coverage](../../../tests/Trykatch.IntegrationTests/OrganizationCacheHttpScopeTests.cs), [generation and commit coverage](../../../tests/Trykatch.IntegrationTests/OrganizationCacheGenerationIntegrationTests.cs), and [adapter integration coverage](../../../tests/Trykatch.IntegrationTests/OrganizationCacheAdapterIntegrationTests.cs).

### Runtime diagnostics

The `Trykatch.OrganizationCache` meter exports `trykatch.cache.reads`, `trykatch.cache.sources`, `trykatch.cache.invalidations`, and `trykatch.cache.refusals`. Every instrument uses only the bounded `mode` and `outcome` dimensions. Read outcomes are `eligible` or `bypassed`; source reads are `started`; refusals identify `dirty`, `oversized`, or `corrupt` payload/state conditions. An invalidation outcome of `staged` means a durable transaction intent was recorded; it is not a count of confirmed commits. These metrics contain no organization, actor, module, read-model, key, DTO, or credential values. The OpenTelemetry filter allowlists only the two bounded dimensions.

The `organization-cache` health check is part of readiness. Disabled and LocalOnly report healthy without touching a backend. Distributed performs a fixed read-only probe with a two-second deadline; success is healthy, while an unavailable optional cache is degraded and source reads remain available. The health response is deliberately minimal and sanitized; it does not include cache keys, endpoints, credentials, vendor errors, or a custom JSON cache claim. The probe does not create keys or mutate generations.

Operational bounds are fixed or validated: default `short` and `standard` TTLs are 30 and 120 seconds; configured TTLs are 1–600 seconds; factory timeout defaults to 5 seconds and is bounded to 1–30 seconds. Factory cancellation is cooperative and scoped work is awaited to completion rather than abandoned. Serialized cache entries are limited to 65,536 bytes. See [cache operations](../../operations/cache.md) for configuration and troubleshooting guidance.
