## Implementation scope

- Public `IModuleJobScheduler` submission supports only authenticated `UserCommand` registrations. `Jobs:Enabled` defaults to false and disabled submission reports `Unavailable`; there is no in-memory scheduler fallback.
- Submission requires a resolved organization and active organization transaction. It locks a trusted `(organization, actor, job key/version, request ID)` scope, then re-resolves current membership, permissions and resource policy before receipt lookup. Identical canonical payload/mode/normalized UTC due time reuses the receipt; changed intent conflicts. The host assigns the opaque WorkId. The enclosing transaction boundary must publish acceptance only after commit.
- Recurring schedules are catalog descriptors plus explicit host `AddModuleRecurringTarget` registrations. They carry a stable schedule/target key, organization, payload, UTC `StartAtUtc` and optional paired catch-up bounds. `StartAtUtc` is inclusive: an occurrence at that instant is eligible. Coalesce keeps the latest nominal occurrence; CatchUp requires 1–100 occurrences and an age no greater than 31 days. Reconciliation visibly fails before cursor advancement if it scans more than 100,000 occurrences.
- Cursor advancement and occurrence work insertion are in one coordinator transaction. Occurrence uniqueness is based on organization/schedule/target/nominal UTC instant, independent of job version. Missing targets pause retained work; compatible registrations can repair it. Configuration mismatch is surfaced rather than silently resetting history.
- Quartz 4.6.0 is configured over existing Npgsql 10.0.3 with the fixed `trykatch_work_coordinator` connection, clustered PostgreSQL ADO store, `infrastructure.qrtz_` prefix, System.Text.Json, string job data, schema validation and no runtime DDL. The Application migration creates the 12 adapted vendor base tables and indexes with FORCE RLS policies for that exact coordinator role; optional execution history is excluded. OpenAPI generation skips hosted scheduler setup. Hosted shutdown requests cooperative interruption and waits for Quartz jobs within the host deadline.
- The work bridge stores only a WorkId reference; the recurring control bridge stores only an explicit schedule/target reference. Restart reconciliation forwards committed work and restores registered recurring controls. Quartz is a trigger adapter; the persisted TryKatch work record remains authoritative.
- Platform listing is bounded and returns an allowlisted DTO without payload, authority context or raw exception. `platform.jobs.read` gates GET; `platform.jobs.manage` gates pause/resume/retry and is not automatically granted. Actions recheck current access, use a request ID and expected recovery generation, lock the work row, and append a control receipt with the mutation. Pause cannot cancel a lease already in flight; completed work cannot be retried. Execution checks current authorization after completion-marker/recovery handling and before starting a new business attempt.

## Schema and rollout boundary

The work coordinator requires exact access to the 12 `infrastructure.qrtz_*` base relations, `infrastructure.module_work_items`, `infrastructure.module_schedule_cursors`, and `infrastructure.module_work_controls`. Quartz tables receive the adapter's required CRUD; work items retain their narrow SELECT/INSERT/UPDATE coordinator profile; schedule cursors use SELECT/INSERT/UPDATE; control receipts use SELECT/INSERT. It receives no business-data grants. Runtime policies and grants must derive from the same access profile and pass live inspection.

The Application migration `20261023221455_AddDurableModuleJobs` adds scheduling fields and the occurrence index to `module_work_items`, creates `module_schedule_cursors` and `module_work_controls`, and creates the 12 Quartz vendor base tables and indexes. It preserves Quartz 4.6.0 PostgreSQL DDL from [`tables_postgres.sql`](https://github.com/quartznet/quartznet/blob/v4.6.0/database/tables/tables_postgres.sql) (SHA-256 `37c62b60adebd683fe96e13e397a2fe40e983317a15d37fba1c5ce3da754d27b`), under Apache-2.0, with adaptations for the `infrastructure` schema, no destructive reset, no optional history, and FORCE RLS policies restricted to `trykatch_work_coordinator`. Do not enable `Jobs:Enabled` against existing volumes until the forward migrator has applied the migration, the runtime-role provisioner grants only the profile above, and live schema/role inspection passes. Apply the one-shot migrator before API deployment; the API must not run migrations during startup.

The isolated Quartz 4.6.0 / Npgsql 10.0.3 dependency graph audit is clean, and the resolved package licenses are permitted (Quartz Apache-2.0; Npgsql PostgreSQL). This result does not close the standard repository advisory baseline: the existing Pkcs, Xml and AppHost MessagePack advisories recorded in E3 remain. Normal locked solution restore still fails on that existing advisory baseline. Diagnostic restore/build/test commands retained audit and visible warnings using `-p:WarningsNotAsErrors=NU1902%3BNU1903`; this does not establish release readiness.
